# Data attribution — `crates/prtip-core/data/`

## `service-probes.txt`

ProRT-IP's service-detection corpus. Generated by
`tools/gen-service-probes/generate.py`; embedded into every binary via
`include_str!` from `crates/prtip-core/src/service_db.rs`.

- **Copyright:** ProRT-IP contributors
- **License:** GPL-3.0-or-later — the same licence as the rest of ProRT-IP
  (`Cargo.toml` declares `license = "GPL-3.0-or-later"`, matching the "or (at
  your option) any later version" grant in `LICENSE` at the repo root)

### Sources

| Source | What it supplies | Licence / terms | URL | Retrieved |
|---|---|---|---|---|
| IANA Service Name and Transport Protocol Port Number Registry | Every port assignment in the corpus | IANA/IETF protocol-parameter registry; published for free use and redistribution (<https://www.iana.org/protocols>) | <https://www.iana.org/assignments/service-names-port-numbers/service-names-port-numbers.csv> | 2026-08-27 |
| Published protocol specifications | Every probe payload and every match expression | Public specifications (IETF RFCs; OASIS MQTT v3.1.1; UPnP Device Architecture 2.0; Microsoft Open Specifications MS-RDPBCGR / MS-CIFS / MS-TDS; project protocol docs for MySQL, MongoDB, PostgreSQL, Redis, memcached, rsync, Git, ZooKeeper, AMQP 0-9-1) | Specifications, not code — the wire formats they describe are facts, not copyrightable expression | see per-probe comments in `tools/gen-service-probes/overlay.txt` | 2026-08-27 |
| Vendor documentation of `Server:` / banner tokens | HTTP and banner product fingerprints | Each product's own public documentation of the string it emits | — | 2026-08-27 |

A reduced snapshot of the IANA registry is committed at
`tools/gen-service-probes/data/iana-ports.tsv` so the corpus is reproducible
offline. `tools/gen-service-probes/fetch-iana.sh` refreshes it.

### Coverage

Real, measured counts for the committed corpus:

| Metric | Count |
|---|---|
| Probes | 37 (25 TCP, 12 UDP) |
| `match` rules | 183 |
| `softmatch` rules | 43 |
| Distinct ports with a port-specific probe | 96 |

This corpus is young. It targets the services that dominate real scan results
(HTTP/TLS, SSH, SMTP/IMAP/POP3, FTP, DNS, SMB, RDP, LDAP, the common databases
and brokers, and the usual UDP services). It does **not** attempt exhaustive
coverage, and it will not identify uncommon, embedded or proprietary services.
Detection rates published anywhere in this repository must reflect that.

### Contributing

Write new rules from a published specification, from a vendor's own
documentation of its banner, or from first-hand observation of a service you
control. Edit `tools/gen-service-probes/overlay.txt`, regenerate, and run
`cargo test -p prtip-core --lib service_db`. See
`tools/gen-service-probes/README.md` and `tools/gen-service-probes/FORMAT.md`.

## `crates/prtip-core/src/top_ports.rs` — the `-F` / `--top-ports` lists

Not in this directory, but the same provenance question applies, so the record
lives here.

`PRIORITY_PORTS_100` and `PRIORITY_PORTS_1000` are generated by
`tools/gen-top-ports/generate.py` from the **same committed IANA registry
snapshot** listed above (`tools/gen-service-probes/data/iana-ports.tsv`,
retrieved 2026-08-27) plus a written ranking rule at
`tools/gen-top-ports/RULE.md`.

- **Copyright:** ProRT-IP contributors
- **License:** GPL-3.0-or-later
- **Sole data input:** the IANA registry snapshot. Nothing else.

The ordering is an **editorial ranking of registry assignments, not a frequency
ranking.** No input to it is a measurement, and ProRT-IP publishes no hit-rate or
coverage figure for it anywhere.

### Licence history — removal of the `nmap-services`-derived ordering

The previous `TOP_100_PORTS` / `TOP_1000_PORTS` arrays were, by their own module
documentation, "based on nmap-services frequency data". `nmap-services` is
NPSL-covered exactly as `nmap-service-probes` is, so that ordering carried the
same defect as the vendored corpus and was removed in the same remediation
programme.

A measured replacement was looked for and none was usable:

| Candidate | Why it was rejected |
|---|---|
| `nmap-services` | NPSL. Reading the file makes the reader a Derivative Work; plain GPL-3.0 distribution is not permitted. |
| scans.io | "The data on the site is restricted to non-commercial use." GPL-3.0 guarantees commercial use, so a GPL-3.0 work cannot carry that restriction. |
| Censys research data | Research access is restricted to non-commercial use and redistribution is forbidden. Same incompatibility. |

ProRT-IP therefore ships an ordering derived only from IANA assignments and says
so plainly, rather than shipping a measured ordering it has no right to
distribute. `-F` and `--top-ports` consequently select a different set of ports
than Nmap and every other frequency-ordered scanner. That difference is
documented in the CLI help, the man page, and the user documentation.

A second, hand-copied duplicate of the same NPSL-derived array in
`crates/prtip-scanner/examples/common_fast_scan.rs` was removed at the same time;
the example now uses the crate constant.

## Licence history — removal of `nmap-service-probes`

This directory previously vendored Nmap's `nmap-service-probes` (17,128 lines,
2.57 MB) and an `ATTRIBUTION.md` that described it as "GPL-2.0 (compatible with
ProRT-IP's GPL-3.0)". **Both parts of that claim were wrong.**

- The file is distributed under the **Nmap Public Source License (NPSL)**, not
  plain GPL-2.0.
- Plain GPLv2 is in any case **not** compatible with GPLv3.

The NPSL states that a work which "Reads or includes Covered Software data
files, such as `nmap-os-db` or `nmap-service-probes`" is a Derivative Work, and
that Derivative Works may not be distributed under plain GPL terms without
permission from the licensor. ProRT-IP declared `license = "GPL-3.0"` and
compiled that file into every binary via `include_str!`, so the combination was
not distributable as licensed.

Remediation, all of it in this change:

1. `crates/prtip-core/data/nmap-service-probes` deleted.
2. Replaced by `service-probes.txt`, written clean-room from the sources in the
   table above. No line of the new corpus was read from, sampled from, or
   derived from any NPSL-licensed file.
3. `ServiceProbeDb::load_from_system()` no longer searches for
   `nmap-service-probes` on disk. Reading it at runtime would itself trigger the
   NPSL Derivative Work clause quoted above; ProRT-IP now looks only for its own
   `service-probes.txt`.
4. Coverage claims across the README, the docs tree and the CLI help were
   corrected to the real numbers above.

### Where the line was drawn

Two kinds of Nmap-shaped material were found during this remediation, and they
were treated differently on purpose.

**Removed as Covered Software.** The vendored corpus and the port ordering are
the *output of Insecure.Com's own measurement and curation*: two decades of
accumulated probe/match rules, and a ranking of ports by observed frequency.
Selection and arrangement of that kind is the substance of the data files the
NPSL names, so both were removed and rebuilt from scratch.

**Kept, being protocol facts rather than anyone's expression.** Some example
and test-fixture lines carried a truncated TLS ClientHello,
`\x16\x03\x00\x00S\x01\x00\x00O\x03\x00`. Every byte of that string is dictated
by the TLS record and handshake layout (RFC 6101 / RFC 2246): a handshake record
type, a version, two length fields, and a ClientHello message type. Any
implementation emitting a minimal ClientHello produces the same bytes, so there
is no authorship in it to license. Those lines were nevertheless rewritten to
use ProRT-IP's own `TLSSessionReq` probe, because after the corpus was replaced
they no longer described what ProRT-IP actually sends — an accuracy fix, not a
licensing one.

The remaining probe-format examples in the `docs/` tree were neither: they were
invented by earlier documentation authors, several with syntax this project's
parser does not accept. They were replaced with real lines from
`service-probes.txt` so that the documentation matches the shipped corpus.
