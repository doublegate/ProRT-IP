# ProRT-IP service-probe overlay
#
# Hand-authored probe payloads and match expressions. Every payload in this file
# was constructed from a published protocol specification; every match expression
# was written from the wire format described in that specification or from the
# vendor's own public documentation of its banner/Server token.
#
# NOTHING in this file is copied, transcribed, sampled or derived from any
# NPSL-licensed source (nmap-service-probes, nmap-os-db) or any other database
# whose licence is incompatible with GPL-3.0.
#
# ---------------------------------------------------------------------------
# Overlay directives
# ---------------------------------------------------------------------------
#   probe <TCP|UDP> <Name> q|<payload>|   start a probe block
#   rarity <1-9>                          1 = always send, 9 = only at max intensity
#   iana <service-name>...                expand to ports via the IANA registry
#   extra-ports <port,port,...>           de-facto ports IANA does not assign
#   sslports <port,port,...>              ports where the probe is wrapped in TLS
#   match / softmatch                     emitted verbatim into the corpus
#
# ---------------------------------------------------------------------------
# Authoring constraints imposed by the ProRT-IP probe format (see FORMAT.md)
# ---------------------------------------------------------------------------
#   * No '|' anywhere in a payload or a pattern (use \x7c for a literal pipe).
#   * p/ v/ i/ h/ o/ d/ values must not contain spaces (use '-').
#   * Patterns are Rust `regex` syntax: no backreferences, no lookaround.
#   * Responses are matched after a lossy UTF-8 conversion, so every non-ASCII
#     byte collapses to U+FFFD and a RUN of invalid bytes may collapse to a
#     SINGLE U+FFFD. Anchor binary patterns on ASCII-range bytes only and use
#     [\s\S] (not a fixed byte) wherever a high byte can appear.
#
# ===========================================================================
# TCP probes
# ===========================================================================

# --- TLSSessionReq: minimal ClientHello -------------------------------------
# Record layer 0x16 / version 0x0301 (RFC 5246 appendix E allows the legacy
# record version); handshake ClientHello 0x01 with client_version 0x0303, a
# fixed 32-byte random, no session id, four cipher suites, null compression,
# no extensions. Structure per RFC 5246 section 7.4.1.2 / RFC 8446 section 4.1.2.
probe TCP TLSSessionReq q|\x16\x03\x01\x00\x35\x01\x00\x00\x31\x03\x03PRTIP-CLIENT-HELLO-RANDOM-32BYTE\x00\x00\x08\xc0\x2f\xc0\x30\x00\x2f\x00\x35\x01\x00\x00\x00|
rarity 2
iana https imaps pop3s ldaps submissions ftps domain-s secure-mqtt
extra-ports 8443,9443,10443
match ssl m|^\x16\x03[\x00-\x04]| p/TLS/ i/server-hello/
match ssl m|^\x15\x03[\x00-\x04]| p/TLS/ i/alert/
softmatch ssl m|^[\x15\x16]\x03|
